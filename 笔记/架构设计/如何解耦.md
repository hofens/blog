当代码量超过一定量的时候，就需要考虑下是否需要解耦。

## 多用组合少用继承
继承：把通用逻辑代码写在一个 base 类中，然后需要通用逻辑的业务类去继承这个 base 类。
继承在项目中很常见，甚至以前我们在初学的时候也会觉得继承是一个良好的设计思维，在代码量不大的时候，这确实是个好的方式，这也让开发倾向于在这个 base 类中增加通用代码，但当 base 类代码量一多起来，其实很难找到我们想要的通用逻辑，对新人了解业务也不太友好。

组合：根据单一职责原则，一个类只实现一个职责或功能，然后按需将这些类放到业务类中。
优点：阅读代码方便，可以知道每个类的作用
需要什么逻辑，就去调用这个类。在代码量庞大的时候，可以很明确的让人知道这个类的作用以及调用该逻辑的原因。
